# AKK Spices — Android ऐप बनाने की गाइड

ऐप खुलते ही पहले **रजिस्ट्रेशन** आता है (Customer / Distributor / Retailer) → **मोबाइल OTP** → ऐप खुलता है →
ऑर्डर से पहले **प्रोफ़ाइल पूरी** करनी पड़ती है।
यह ऐप आपकी साइट `https://akkspices.in/app/` को Android ऐप के अंदर खोलता है, इसलिए कीमतें, GST इनवॉइस,
UPI पेमेंट और डिलीवरी के नियम वेबसाइट जैसे ही रहते हैं। साइट में कुछ बदलोगे तो ऐप में अपने-आप दिखेगा।

> ⚠️ मैंने यह सब ब्राउज़र में (नकली Supabase के साथ) टेस्ट किया है। असली SMS, असली Android फ़ोन और UPI ऐप खुलना
> मैं यहाँ टेस्ट नहीं कर पाया। इसलिए नीचे "टेस्ट" वाला हिस्सा ज़रूर करें।

---

## भाग A — Supabase में (सबसे पहले)

### A1. SQL चलाएँ
Supabase → **SQL Editor → New query** → फ़ाइल `SUPABASE-APP-OTP.sql` का पूरा टेक्स्ट paste करें → **Run**।
- `customers` टेबल बनती है (ग्राहकों की प्रोफ़ाइल)।
- **ज़रूरी सुरक्षा सुधार:** पहले कोई भी साइन-अप किया हुआ यूज़र ब्राउज़र से अपना पार्टनर `status` सीधे `approved` लिखकर
  डाल सकता था। अब नई पार्टनर row सिर्फ़ `pending` बन सकती है। अप्रूव आप ही करेंगे।

### A2. फ़ोन OTP चालू करें
Supabase → **Authentication → Sign In / Providers → Phone** → Enable।
1. **SMS provider चुनें और उसकी key भरें।** Supabase सीधे Twilio, MessageBird, Vonage और Textlocal के साथ चलता है।
2. **भारत में SMS भेजने के लिए DLT रजिस्ट्रेशन चाहिए** (sender ID और OTP टेम्पलेट अप्रूव होना ज़रूरी)। इसके बिना कई
   प्रोवाइडर के OTP पहुँचते ही नहीं। यह काम आपके SMS प्रोवाइडर के साथ होता है।
3. हर OTP के पैसे लगते हैं (प्रोवाइडर के रेट के हिसाब से)।
4. MSG91 / Fast2SMS जैसे भारतीय प्रोवाइडर सीधे लिस्ट में नहीं हैं। उनके लिए Supabase का "Send SMS Hook"
   (एक छोटा Edge Function) लगता है। चाहें तो मुझसे बनवा लें।
5. **बिना SMS के टेस्ट:** उसी पेज पर **"Phone numbers for testing"** में एक नंबर और उसका फ़िक्स OTP डालें
   (जैसे `919999900000=123456`)। उस नंबर पर असली SMS नहीं जाएगा और टेस्ट आसानी से हो जाएगा।
   **Play Store रिव्यू के लिए भी यही टेस्ट नंबर Google को देना होगा** (नीचे भाग D देखें)।
6. OTP की लंबाई 6 अंक रखें (ऐप 6 अंक माँगता है)।

## भाग B — फ़ाइलें अपलोड करें

1. **cPanel (`public_html`)**: `1-cpanel-akkspices-website.zip` Extract करें (पुरानी फ़ाइलें ओवरराइट होंगी)।
   नए हिस्से: `app/` फ़ोल्डर (welcome, profile, launcher) और `app-gate.js`।
2. **Vercel**: इस बार API में कोई बदलाव नहीं है। अगर पिछली Vercel ज़िप पहले ही डाल चुके हैं तो कुछ नहीं करना।

### फ़ोन के ब्राउज़र में पहले टेस्ट करें
Android फ़ोन के Chrome में यह खोलें: `https://akkspices.in/app/index.html?app=1`
- रजिस्ट्रेशन पेज आना चाहिए → role चुनें → मोबाइल नंबर → OTP → प्रोफ़ाइल → शॉप।
- बिना प्रोफ़ाइल पूरी किए Checkout खोलने पर प्रोफ़ाइल पेज पर वापस आना चाहिए।
- (सामान्य वेबसाइट पर, बिना `?app=1` के, कुछ नहीं बदलता: रजिस्ट्रेशन सिर्फ़ ऐप में माँगा जाता है।)

## भाग C — APK / AAB बनाना (आपके कंप्यूटर पर)

ज़रूरी: **Node.js 20+** और **Android Studio** (SDK के साथ)।

```
cd android-app
npm install
npx cap add android          # android/ फ़ोल्डर बनाता है (सिर्फ़ पहली बार)
npm run assets               # resources/icon.png और splash.png से आइकन व स्प्लैश बनाता है
npx cap sync android
npx cap open android         # Android Studio खुलेगा
```

Android Studio में:
1. फ़ोन USB से जोड़ें (USB debugging चालू), ▶ Run दबाएँ → ऐप फ़ोन पर खुलेगा। **पूरा फ़्लो टेस्ट करें:**
   OTP, प्रोफ़ाइल, ऑर्डर, **UPI पेमेंट (UPI ऐप खुलता है या नहीं)**, WhatsApp बटन, पार्टनर पोर्टल।
2. रिलीज़ के लिए: **Build → Generate Signed Bundle / APK → Android App Bundle (AAB)**।
   नई keystore बनाएँ और उसे **पासवर्ड समेत कई जगह सुरक्षित रखें**। यह खो गई तो ऐप का अपडेट कभी नहीं डाल पाएँगे।
3. हर नए वर्ज़न पर `android/app/build.gradle` में `versionCode` +1 करें।

> ऐप हमेशा `akkspices.in` से लोड होता है, इसलिए इंटरनेट ज़रूरी है। इंटरनेट न हो तो "इंटरनेट चालू करें" वाला पेज आता है।

## भाग D — Google Play Store

1. **Google Play Developer अकाउंट** (एक बार की फ़ीस, लगभग $25)।
2. Play Console → Create app → AAB अपलोड करें।
3. **Privacy policy URL:** `https://akkspices.in/privacy.html`
4. **Data safety फ़ॉर्म में बताएँ कि ऐप ये डेटा लेता है:** फ़ोन नंबर, नाम, पता, ईमेल (वैकल्पिक), ऑर्डर की जानकारी।
5. **App access (लॉगिन वाले ऐप के लिए ज़रूरी):** Google रिव्यूअर को असली OTP नहीं मिल सकता। इसलिए भाग A2 वाला
   **टेस्ट फ़ोन नंबर + फ़िक्स OTP** यहाँ लिखकर दें, वरना ऐप रिजेक्ट हो सकता है।
6. स्क्रीनशॉट, छोटा/लंबा विवरण, कंटेंट रेटिंग भरें। पहली बार रिव्यू में कुछ दिन लग सकते हैं।

## ऐप कैसे चलता है (काम का सार)

| कौन | क्या होता है |
|---|---|
| **Customer** | OTP → नाम, पता, शहर, राज्य, PIN भरता है → शॉपिंग। चेकआउट पर जानकारी अपने-आप भरी मिलती है। |
| **Retailer** | OTP → दुकान की जानकारी → आवेदन `pending`। आप Supabase में `approved` करें, तब पार्टनर पोर्टल से ऑर्डर कर सकेगा। सिर्फ़ उन इलाक़ों से जहाँ आपका डिस्ट्रीब्यूटर है (अभी समस्तीपुर)। |
| **Distributor** | OTP → व्यापार की जानकारी → आवेदन `pending` → आपके अप्रूव करने पर किट व थोक ऑर्डर। |
| **पुराने ईमेल वाले पार्टनर** | रजिस्ट्रेशन पेज पर "ईमेल से लॉगिन" लिंक से पहले जैसे लॉगिन कर सकते हैं। |

**अप्रूवल:** Supabase → Table Editor → `partners` → उस पार्टनर की `status` को `approved` करें (पहले जैसा ही तरीका)।
**ग्राहकों की लिस्ट:** Table Editor → `customers`।

## अभी सीमाएँ (ईमानदारी से)
- ऑर्डर से पहले प्रोफ़ाइल पूरी होने की रोक **ऐप में** लगती है (क्लाइंट की तरफ़)। पार्टनर ऑर्डर पर सर्वर भी `approved` की जाँच करता है। शॉपिंग ऑर्डर की सर्वर-साइड रोक अभी नहीं है।
- अगर आप चाहते हैं कि एक ही फ़ोन नंबर पर ग्राहक और पार्टनर दोनों हों, तो वह चलेगा, पर पार्टनर वाला रास्ता पहले खुलेगा।
- iPhone ऐप इस प्रोजेक्ट में नहीं है।
